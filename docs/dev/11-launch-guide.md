## 1. Supabase の準備（15 分）

Supabase は、端末どうしのメッセージを中継するサービスです。SUKIMA はデータベース（表）を使わないので、**表を作る作業や SQL（データベースの命令文）は不要**です。

### 1-1. アカウントとプロジェクトを作る

1. https://supabase.com を開き、「Start your project」（または「Sign up」）から登録する。「Continue with GitHub」で GitHub のアカウントを使うと楽です。
2. 最初に「Organization」（プロジェクトをまとめる入れ物）を作るよう言われたら、名前は何でもよい（例：`sukima`）。種類は「Personal」、プランは「Free」（無料）を選ぶ。
3. 「New project」を押し、次のように入れる。
   - 「Project name」：`sukima`（何でもよい。外には出ません）
   - 「Database Password」：「Generate a password」で作り、**パスワード管理アプリに保存**。SUKIMA では使いませんが、あとで必要になることがあります。**このパスワードはどこにも貼らない**
   - 「Region」（サーバーの場所）：**Northeast Asia (Tokyo)** を選ぶ
4. ほかの項目は最初のまま（要確認：作成画面に見慣れない項目が増えていたら、最初のままで進めてよい）。「Create new project」を押す。準備に 1〜2 分かかります。

**東京を選ぶ理由**：遊ぶ人の多くは日本にいます。サーバーが近いほど、操作が相手の画面に届くまでの待ちが短くなります（ラッシュの「済」の表示や、指スマの掛け声が届く速さに効きます）。**場所はあとから変えられない**ので、ここだけは確かめてから押してください。「Asia-Pacific」のような広い地域だけを選ぶ方式もあるようですが、東京と書かれたものを選びます（要確認）。

### 1-2. URL と anon キーを控える

SUKIMA に入れる値は 2 つだけです。

1. 左のメニューの歯車「Project Settings」を開く。
2. **Project URL**：「Data API」または「API」の項目にある `https://（英数字）.supabase.co` の形のもの（要確認：画面上部の「Connect」ボタンからも見られます）。
3. **anon キー**：「API Keys」を開き、**「Legacy API Keys」のタブ**にある `anon` `public` と書かれたキーをコピーする。`eyJ` で始まる長い文字列です。
4. 2 つをメモ帳などに一時的に控える（§2 で Cloudflare に貼ります）。

> **新しい形式のキー（`sb_publishable_` で始まる）について**：Supabase は古い形式（anon キー）を 2026 年の終わりごろに廃止する予定と案内しています（時期は未確定）。今の SUKIMA の作りでは、新しい形式のキーでつながるかを**まだ確かめていません**。
> - 「Legacy API Keys」タブに `eyJ…` の anon キーがあれば、それを使ってください。
> - **タブがない・キーが無効になっている**ときは、そこで止めてチャットに知らせてください。こちらで新しい形式に対応させてから進めます。

### 1-3. 絶対に貼ってはいけないもの

サイトに入れてよいのは **anon キー（`anon` `public`）だけ**です。サイトに入れた値は、誰でも見られる状態になります。次のものは、Cloudflare にも、チャットにも、どこにも貼らないでください。

| 貼ってはいけないもの | 見分け方 |
| --- | --- |
| `service_role` キー | 「Legacy API Keys」で anon の下にある。`secret` と書かれている |
| secret キー | `sb_secret_` で始まる |
| Database Password | 1-1 で作ったパスワード |
| JWT Secret | 「JWT Keys」などの画面にある |

- これらが漏れると、プロジェクトを好きに操作されるおそれがあります。**間違えて貼ったら、すぐチャットで知らせてください**（キーの作り直しを案内します）。
- anon キーは、サイトを開けば誰でも見られる前提の値なので、チャットに貼っても問題ありません。

### 1-4. 「公開チャンネル」を許可したままにする

SUKIMA は誰でも入れる「公開チャンネル」（部屋ごとの通信の通り道）を使います。これを禁止する設定が**オフ**になっている必要があります。

1. 左のメニューの「Realtime」→「Settings」を開く（要確認：「Project Settings」→「Realtime」の場合もあります）。
2. **「Allow public access」がオン（Enabled）** になっていることを確かめる。最初からオンのはずです。
   - 以前の資料で「Private channels only をオフにする」と書いていたのは、この設定のことです（画面の名前が変わりました）。「Private channels only」という名前で出ていたら、そちらは**オフ**にします。
3. ほかの設定は触らない。

### 1-5. 無料プランの上限と、使用量の見方（D-09 の条件）

**上限（2026-11-14 に検索で確認。公式ページの本文は未確認なので、作成時に料金ページで数字を見てください）**

| 項目 | 無料プラン | SUKIMA での目安（設計時の見積もり・仮定） |
| --- | --- | --- |
| 同時につながる端末 | 200 台 | 10 人部屋なら 20 部屋分 |
| メッセージ数／月 | 200 万件 | 4 人でラッシュを遊ぶと月 80 時間分ほど |
| メッセージ／秒（全体） | 100 件 | 10 人部屋 2〜3 部屋が同時に盛り上がると届く |
| 無料で持てるプロジェクト | 2 つ | SUKIMA は 1 つ |

- **超えたら**：無料プランは自動で課金されません。警告メールが来て、超えた状態が続くと**つながらなくなる**（利用が止められる）方式です。月が変わると戻ります。つまり**無料プランそのものが「利用上限」になります**（D-09 の「利用上限」はこれで満たします）。
- 1 秒あたりの上限を超えると、その瞬間に全員の接続が切れます（自動でつなぎ直します）。
- **気をつけること：7 日間「使われていない」と、無料のプロジェクトは一時停止されます**。Supabase の説明では「データベースの利用」で判断するとされていますが、SUKIMA はデータベースを使いません。**遊ばれていても停止される可能性があります**（要確認）。停止の 1 週間ほど前に警告メールが来ます。停止されたら、Supabase の画面の「Restore project」で戻せます（数分かかります）。§6 の週 1 回の確認で見てください。

**使用量の見方**

1. Supabase の画面の左上で Organization（1-1 の手順 2 で作った入れ物）を選び、「Usage」を開く（要確認）。
2. 「Realtime Messages」（メッセージ数）と「Realtime Peak Connections」（同時接続の最大）を見る。
3. **上限の 70% を超えていたら**（メッセージ数なら 140 万件）、チャットで知らせてください（D-01 の条件。有料プランに移るか、通信を減らすかを相談します）。

## 2. Cloudflare Pages で公開する（20 分）

Cloudflare Pages は、サイトのファイルを置いて世界中に配るサービスです。GitHub とつなぐと、`main`（公開用の本流）に変更が入るたびに自動で作り直して公開します。

### 2-1. つなぐ

1. https://dash.cloudflare.com を開いて登録する（メールの確認があります）。
2. 左のメニューの「Workers & Pages」（または「Compute」の中）を開き、「Create application」（または「Create」）を押す。
3. **「Pages」を選ぶ**。最初の画面は「Workers」（別の仕組み）向けになっていて、Pages は画面の下の「Looking to deploy Pages? Get started」のような小さなリンクや「Pages」タブにあることがあります（要確認）。
   - **間違いやすいところ**：「Deploy command」「wrangler」という欄が出たら、Workers の画面です。戻って Pages を選び直してください。完成したサイトの URL が `workers.dev` で終わっていたら、Workers で作ってしまっています。
4. 「Import an existing Git repository」（または「Connect to Git」）→「GitHub」を選ぶ。GitHub の画面に移ったら、Cloudflare に見せるリポジトリ（コードの置き場所）として **「Only select repositories」→ `nats2424/yubisuma`** を選んで許可する。
5. Cloudflare に戻り、`yubisuma` を選んで「Begin setup」を押す。

### 2-2. ビルドの設定（ビルド＝公開用のファイルを作る作業）

次のとおり入れます。

| 項目 | 入れる値 | メモ |
| --- | --- | --- |
| 「Project name」 | 決めた名前（例：`sukima`） | **これがそのまま `sukima.pages.dev` になります。あとから変えられません**（変えるには作り直し）。小文字の英字・数字・ハイフンだけ。使われている名前のときの扱いは要確認 |
| 「Production branch」 | `main` | |
| 「Framework preset」 | `None`（「Vite」があればそれでも可） | 下の 2 つを手で入れるので、どちらでもよい |
| 「Build command」 | `npm run build` | |
| 「Build output directory」 | `dist` | `build` ではなく `dist` |
| 「Root directory」 | 空のまま | |

続けて「Environment variables (advanced)」（環境変数＝ビルドのときに渡す設定値）を開き、「Add variable」で 3 つ入れます。

| 「Variable name」 | 「Value」 |
| --- | --- |
| `VITE_SUPABASE_URL` | 1-2 の Project URL（`https://….supabase.co`） |
| `VITE_SUPABASE_ANON_KEY` | 1-2 の anon キー（`eyJ…`） |
| `NODE_VERSION` | `22` |

- 名前は 1 文字でも違うと効きません。**コピーして貼る**のが確実です。値の前後に空白が入らないようにします。
- 種類を選べるときは「Text」（暗号化しない方）でかまいません。anon キーは公開してよい値です（要確認：「Secret」を選ぶとビルドで読めない場合があるため、Text を勧めます）。
- `NODE_VERSION` は、ビルドに使う Node.js（JavaScript を動かす道具）の版を決めます。今の Cloudflare の標準は 22 系なので入れなくても動く見込みですが、標準が変わっても壊れないように固定します。SUKIMA が使う Vite 8 は Node.js 20.19 以上か 22.12 以上が必要です。
- `VITE_BASE` は入れません（サイトの一番上の階層に置くため不要）。

最後に「Save and Deploy」を押します。2〜3 分で終わります。

### 2-3. 公開できたか確かめる

1. 「Success」と出たら、表示された `https://（名前）.pages.dev` を開く。
2. **トップに次の帯が出ていなければ OK** です。
   「デモモード：Supabase未設定のため、同じブラウザ内の別タブ同士でのみ遊べます（README参照）。」
3. 名前を入れて「部屋を作る」を押し、「接続中…」のあとに部屋（ロビー）が開けば、Supabase につながっています。
4. 帯が出ている・「接続できませんでした」になるときは §5 へ。

### 2-4. 知っておくこと

- **環境変数を直したら、作り直しが必要**です。値はビルドのときにサイトに埋め込まれるためです。「Deployments」→ 一番上の公開 →「…」→「Retry deployment」で作り直せます（要確認）。
- **プレビュー用の設定**：`main` 以外の枝（試作の版）も、自動で `（枝の名前）.（名前）.pages.dev` に公開されます。こちらにも同じ環境変数が入っているか、「Settings」→「Variables and Secrets」（または「Environment variables」）で「Preview」を選んで確かめてください（要確認：最初の設定が本番用だけに入る場合があります）。入っていないと、試作の版はデモモードになります。
- ビルドは無料プランで**月 500 回まで、1 回 20 分まで、同時に 1 つ**です。SUKIMA のビルドは 1 分ほどで、`main` に入れる回数も月 500 回には届かない見込みです。
- サイトの転送量（見られた量）に上限はない（無料で無制限）とされています（要確認：公式の規約の文面）。

## 3. 手元の端末で確認する（30〜40 分）

公開前の最後の確認です（D-03・D-04）。仕様の AC-M1〜M5（`docs/dev/01-pdm-spec.md` §7.9）を、1 人でできる形にしました。**M1〜M4 が OK なら公開してよい**条件です（D-04、WBS H-4）。

### 3-0. 準備

- 端末：PC（Chrome）・iPhone（Safari）・Android（Chrome）。ない端末は飛ばして、手持ちの 2 台以上で行う。
- すべての端末で `https://（名前）.pages.dev` を開き、デモモードの帯が出ていないことを確かめる。
- 端末ごとに違うニックネームにする（例：PC・iPhone・Android）。
- 何かおかしかったら、その場で**スクリーンショット**と**時刻**を控える。

### だめなときに送ってほしいもの（全項目で共通）

1. どの項目か（例：M2）
2. 端末とブラウザ（例：iPhone の Safari、Android の Chrome、PC の Chrome）
3. 何をしたか・何が見えたか（スクリーンショット。画面の文言が分かるもの）
4. だいたいの時刻と、部屋コード（4 文字）
5. かかった秒数（分かれば）
6. 通信（Wi-Fi か、モバイル回線か）
7. できれば：PC なら F12 キー →「Console」タブで赤い文字が出ていればそのスクリーンショット（できなければ不要）

### チェックリスト

**□ M1：3 台が 10 秒以内に部屋に入れる**

- する：
  1. PC で名前を入れて「部屋を作る」。
  2. 部屋の上の「招待する」を押す（URL がコピーされます。スマホで押すと共有の画面が出ます）。
  3. その URL を LINE の自分用のトーク（Keep メモなど）やメールで iPhone・Android に送る。
  4. iPhone は URL を長押しして「Safari で開く」、Android は Chrome で開く。名前を入れて「参加する」。押してから何秒で部屋に入れたかを数える。
- OK：どの端末も「参加する」から **10 秒以内**に部屋の画面になり、**3 台すべての画面のメンバー一覧に 3 人が並ぶ**。PC の名前の横に「ホスト」の札がある。
- だめ：10 秒を超える、「接続できませんでした」「部屋 ○○ が見つかりません」が出る、メンバーが揃わない。
- おまけ（できれば）：LINE のトークの URL をそのままタップして開く（LINE の中のブラウザ）でも入れるか。LINE に一度戻ってから部屋に戻れるか（通話中に遊ぶ場面の確認。07 の J-15）。

**□ M2：機内モードから自動で戻る**

- する：M1 の部屋のまま、**ホストではない**スマホ（例：Android）を機内モードにして 5 秒待ち、機内モードを解除する。
- OK：そのスマホの画面上部に「再接続中… 自動でつなぎ直しています」の帯が出て、**何も押さずに帯が消え**、元の部屋に戻る。ほかの端末の一覧で、そのスマホが「（オフライン）」→ 元に戻る。帯が消えるまでの秒数を控える（1 分以内なら OK。仕様に秒数の決まりはないため、記録して判断します）。
- だめ：帯が消えない（1 分以上）、「接続できませんでした」や「部屋が見つかりません」になる、戻ったら名前が別人として増えている。
- 機内モード中に Wi-Fi が勝手にオンになる端末は、Wi-Fi もオフにする。

**□ M3：ホストがスリープしても遊びが続く**

- する：
  1. **iPhone で新しく部屋を作り**（iPhone がホスト）、PC と Android も入る。
  2. iPhone で「指スマ」か「ミニゲームラッシュ」を選んで「スタート」。
  3. ゲームの途中で iPhone の横のボタンを押して画面を消し、**30 秒待つ**。
  4. iPhone の画面をつけ、Safari に戻る。
- OK：iPhone が消えている間、PC と Android ではゲームが止まらずに進み、どちらかの名前に「ホスト」の札が移る。iPhone は戻ったあと、**ほかの 2 台と同じ場面**（同じステージ・同じ順番）が表示され、「ホスト」の札は付いていない。
- だめ：PC と Android で進まなくなる、iPhone が戻ったときにゲームが前の場面に戻る（巻き戻る）、ホストが 2 人いる状態が 10 秒以上続く、「部屋が見つかりません」になる。
- 巻き戻りは、見送った不具合 QA-BUG-05（D-10）に関係するかもしれません。起きたら必ず知らせてください。

**□ M4（1 人でできる範囲）：ラッシュの「クリア／ミス」が手応えどおり**

- する：3 台で「ミニゲームラッシュ」を最後まで遊ぶ。1 人では全部を同時に操作できないので、役を分ける。
  - 1 台目：ちゃんと遊ぶ
  - 2 台目：何も触らない
  - 3 台目：わざと間違える（または遅れて押す）
- OK：1 台目は自分の手応えどおりに「クリア！」「ミス！」が出る。2 台目・3 台目は「ミス！」になり、ハート（ライフ）が減る。最後まで進み、結果が全員に出る。
- だめ：正しく押したのに「ミス！」、触っていないのに「クリア！」、途中で止まる、端末によって結果が違う。どのステージ（何のミニゲーム）だったかも添えてください。

**□ 確認が終わったら**

- チャットに「M1〜M4 OK」または、だめだった項目と上の「送ってほしいもの」を送る。
- OK なら公開してよい状態です（D-04）。

### 知り合いに頼む（1 人では確かめにくい項目）

試遊（08 の Phase 0）や、友達と通話するついでに頼むのが楽です。

**□ M4（完全版）**：3 人がそれぞれ自分の端末で、ラッシュを最後まで本気で遊ぶ。終わったら「判定が自分の感覚と合っていたか」を 1 人ずつ聞く。合わなかった人がいたら、その人の端末とどのミニゲームだったかを送ってください。

**□ M5：10 人で 5 分遊んでも切れない**

- する：10 人（足りなければ、PC で**別々のウィンドウ**を開いて人数を足してよい）で同じ部屋に入り、ラッシュとチャットで 5 分遊ぶ。
  - 人数を足すときは、**新しいウィンドウに URL を貼って開く**。「タブを複製」は使わない（同じ人として扱われるため）。
  - 足したウィンドウは**画面に見えるように並べる**。裏に隠れたタブは、ブラウザが動きを遅くするので、切れたように見えることがあります。
- OK：5 分の間、全員の画面で「再接続中…」の帯が出ず、メンバーが「（オフライン）」にならない。
- だめ：何人かが同時に「再接続中…」になる（Supabase の 1 秒あたりの上限に当たった可能性）。時刻と人数を送ってください。こちらで Supabase の記録と照らし合わせます。

## 5. よくあるつまずきと対処

| 症状 | よくある原因 | 対処 |
| --- | --- | --- |
| 公開したのにトップに「デモモード」の帯が出る | 環境変数が入っていない・名前が違う。または、入れたあとに作り直していない | §2-2 の表と見比べ、名前を貼り直す。直したら §2-4 の「Retry deployment」で作り直す。ブラウザの再読み込みも行う |
| 試作の版（`○○.名前.pages.dev`）だけデモモード | プレビュー用に環境変数が入っていない | §2-4 のとおり「Preview」にも入れる |
| 「接続中…」のまま、または「接続できませんでした」 | URL かキーの貼り間違い（前後の空白、途中で切れた）。新しい形式のキーを入れた。「Allow public access」がオフ | §1-2 の anon キー（`eyJ…`）を貼り直して作り直す。§1-4 を確かめる。それでもだめならスクリーンショットを送る |
| しばらくぶりに開いたら、全員つながらない | Supabase の一時停止（7 日使われない）、または使用量の上限 | Supabase の画面でプロジェクトに「Paused」などの表示があれば「Restore project」。Usage で上限を超えていないか見る。どちらでもなければチャットへ |
| ビルドが失敗する（「Failed」） | 設定の入れ間違い（出力先が `dist` でない等）、Node.js の版 | §2-2 の表と見比べる。直らなければ、失敗した公開を開いて「Build log」（作業の記録）の最後の 30 行ほどのスクリーンショットを送る |
| サイトの URL が `workers.dev` で終わる | Pages ではなく Workers で作った | そのプロジェクトは消して、§2-1 の手順 3 から Pages で作り直す |
| 名前の欄に希望の名前が入れられない | すでに使われている名前 | 別の候補（例：`sukima-game`、`sukima-play`）にする。名前の候補はチャットで相談してもよい |
| GitHub に `yubisuma` が出てこない | GitHub 側で許可していない | GitHub の「Settings」→「Applications」→ Cloudflare の設定で、`nats2424/yubisuma` を許可に入れる（要確認） |
| 公開したのに、直した内容が出ない | まだ `main` に入っていない、作り直し中 | Cloudflare の「Deployments」で一番上が「Success」か見る。ブラウザを再読み込みする |

## 6. 公開したあとにやること（週 5 分）

PO の時間を増やさないよう、最小限にしています。

**週 1 回（5 分）**

1. Supabase の「Usage」を開き、メッセージ数が**上限の 70%（140 万件）を超えていないか**を見る。超えていたらチャットで知らせる（D-01）。
2. Supabase のプロジェクトが「一時停止（Paused）」になっていないかを見る。なっていたら「Restore project」を押して、チャットで知らせる。
3. Supabase・Cloudflare から警告のメールが来ていないかを見る。来ていたら転送する。

**なにもしなくてよいこと**

- 公開の作業：`main` に変更が入ると自動で公開されます。
- Cloudflare の料金：無料プランのままで、自動で課金されることはありません。

**こんなときは知らせてください**

- 「つながらない」と言われた（いつ・どの端末か）
- Supabase か Cloudflare から、規約や料金の変更・停止のメールが来た
