## 0. 前提：いまの体験の骨格（コードで確認した事実）

| 項目 | 事実 | 根拠 |
| --- | --- | --- |
| 入口 | トップ（`#/`）・ルーム（`#/r/ABCD`）・ひとり用（`#/practice`）の 3 つ。ハッシュルーティング | `App.tsx` |
| 名前 | ニックネーム（10 文字まで）は `localStorage` に保存。**保存済みなら招待 URL を開いた瞬間に参加画面を飛ばして自動で入室**する。部屋の中で名前は変えられない | `Room.tsx` の `confirmed` 初期値、`identity.ts` |
| プレイヤー ID | **タブごと**（`sessionStorage`）。同じタブのリロードなら同じ人として復帰。別タブ・別ブラウザで開くと別人になる | `identity.ts` `getPlayerId` |
| 部屋の寿命 | サーバーに部屋は残らない。**全員が抜けたら部屋は消える**。古い URL を開くと接続後 8 秒で「部屋 XXXX が見つかりません」＋「このコードで部屋を作る」 | `engine.ts` `JOIN_TIMEOUT_MS`、`Room.tsx` `notfound` |
| 招待 | ヘッダー右上の小さい「招待する」ボタン。スマホは Web Share（共有シート）、PC は URL をコピー。共有文は「SUKIMAで遊ぼう！ 部屋コード: XXXX」＋URL のみ | `Room.tsx` `ShareButton` |
| URL プレビュー | `index.html` は `<title>` と `description` だけ。**OGP（og:image など）・twitter:card なし**（AC-40 未実装） | `index.html`、04 §AC-40 |
| ロビーの既定ゲーム | 部屋を作ると「ワードウルフ」（3〜10 人）が選択済み。ホスト 1 人では「スタート」が押せず「あと2人必要です。『招待する』からURLを送りましょう。」と出る | `registry.ts` `DEFAULT_GAME`、`Room.tsx` `SelectedGame` |
| 2 人で遊べるゲーム | 反射神経バトル・ミニゲームラッシュ・指スマのみ（ワードウルフ・多数派・大富豪は 3 人〜） | `registry.ts` |
| 結果画面 | 各ゲームの最終結果パネル（順位と🏆）。「もう一度」「ロビーへ」は**ホストにだけ、ゲーム見出し横の小さいゴーストボタン**として出る。ゲスト側の結果画面には「ホストが次を決めるのを待っています」の表示がない | `Room.tsx` `GameArea`、`rush/View.tsx` ほか |
| 数値の表示 | ラッシュ・ひとり用は「n ステージ クリア」（方針どおり）。一方で多数派は「n pt」、反射神経は「n ms」を表示 | `majority/View.tsx`、`reaction/View.tsx` |
| ひとり用 | 名前不要で即スタート。ライフ 4、ゲームオーバーで「n ステージ クリア」「自己ベスト更新！」、「もう一度」「戻る」。**記録の共有・友達と遊ぶ導線はない**。自己ベストは `localStorage`（端末・ブラウザごと） | `Practice.tsx` |
| 再訪のフック | 最近の部屋・前回のメンバー・通知・ホーム画面アイコン（manifest / apple-touch-icon）はいずれもない | `index.html`、`public/` |
| 計測 | **アナリティクス・ログ送信は一切ない**。何ルーム作られ、何ゲーム遊ばれたか誰にも分からない | `src` 全体を検索 |
| 実通信 | Supabase 実機での確認（AC-M1〜M4）は**未実施**。デモモードのまま公開すると別端末では遊べない（トップに帯は出る） | 04 §1.9、`Layout.tsx` |

凡例：改善の優先度 **Must**（公開・PMF 検証の前に必要）/ **Should**（Phase 1 中に入れたい）/ **Could**（余裕があれば・検証結果次第）。工数 **S**（〜半日）/ **M**（1〜3 日）/ **L**（1 週間〜、または契約・設計変更を伴う）。ID は §4 の横断一覧と対応する。

## 1. 幹事ユウキ（P1・持ち込む人）

### 4.1 PdM の所見

- **Must の 8 件のうち 6 件は S 工数**。公開前（Phase 0 の試遊と並行）に入れられる。特に J-03・J-04・J-02 は文言とボタン配置だけで、北極星指標（`08` §1.2）に直結する。
- 体験の「中」（参加画面・ロビー・ミニゲーム）は案B と例外系の実装で既にかなり良い。**弱いのは「外」**：URL が届いた瞬間（OGP・共有文）、結果の後（次の行動）、離脱の後（再訪・広める）。PMF の成否はここで決まる。
- J-09（参加前に待っている人を見せる）は効果が大きそうだが契約変更なので、J-01・J-03 の効果を Phase 0〜1 で測ってから判断する。
