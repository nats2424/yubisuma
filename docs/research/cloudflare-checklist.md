# Cloudflare Pages で公開する前に調べること

SUKIMA は静的ファイルだけのサイト（`npm run build` の `dist/`）で、通信は Supabase Realtime に直接つなぐ。
サーバー処理（Functions / Workers）は今は使わない。この前提で、公式情報（cloudflare.com、developers.cloudflare.com の利用規約・料金・制限のページ）を確認する。

## 1. 規約（いちばん大事）
- [ ] **無料プランで商用利用してよいか**。収益化（法人向けプラン・スポンサーお題・投げ銭リンク・将来の広告）を始めたあとも無料プランのままでよいか
- [ ] 個人（法人なし）で使ってよいか。運営者の表示が必要か
- [ ] 利用規約で禁止されている用途に、SUKIMA（ブラウザゲーム、ユーザー同士のチャット）が当たらないか
- [ ] 規約違反と判断されたときの扱い（警告なしの停止があるか）

## 2. 無料プランの制限
- [ ] 静的ファイルの**転送量・リクエスト数に上限があるか**（「無制限」とする情報が多いが、公式で確認）
- [ ] ビルド回数（月 500 回とされる）と、1 回のビルド時間の上限（20 分とされる）。アカウント全体か、サイトごとか
- [ ] 1 サイトのファイル数・1 ファイルのサイズの上限（今のビルドは JS 約 330KB と画像数点で、問題ない見込み）
- [ ] 同時に動くビルドの数
- [ ] 上限を超えたときに、サイトが止まるのか・課金されるのか

## 3. ドメイン（D-02）
- [ ] 無料の `○○.pages.dev` の名前の決まり方（`sukima.pages.dev` を取れるか）
- [ ] 独自ドメインをつなぐ手順と費用（Cloudflare でドメインを買う場合・他社で買ったドメインをつなぐ場合）
- [ ] HTTPS が自動で有効になるか
- [ ] `pages.dev` から独自ドメインに移すときの転送（リダイレクト）の設定方法。※ドメインを変えると、ブラウザに保存した自己ベストなどは引き継がれない

## 4. 公開の運用
- [ ] GitHub（`nats2424/yubisuma` の `main`）とつないで、push するたびに自動で公開できるか
- [ ] Pull Request ごとのプレビュー URL が使えるか（試遊で新しい版を試すのに便利）
- [ ] 環境変数（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`）をビルド時に渡す方法
- [ ] ビルドの設定（Node のバージョン、ビルドコマンド `npm run build`、出力先 `dist`）
- [ ] ルートで公開するなら `VITE_BASE` は不要であることの確認

## 5. プライバシー・計測（D-12）
- [ ] Cloudflare 側で取られるアクセスログ（IP など）の扱いと保存期間。プライバシーの説明に書く必要があるか
- [ ] **Cloudflare Web Analytics**（Cookie なしの無料の計測）が使えるか。使えるなら、匿名計測の候補（今は Umami を想定）と比べる
- [ ] 計測のスクリプトを入れた場合に、Cookie の同意表示が必要になるか

## 6. 将来、必要になりそうなもの
- [ ] Workers 有料プラン（月 5 ドルとされる）で何が増えるか。サポーターパスの購入処理に小さなサーバー処理が要るとき、Workers / Pages Functions で作れるか
- [ ] DDoS や大量アクセスへの標準の保護が無料プランに含まれるか
- [ ] 障害時のステータスページ・サポート窓口（無料プランで受けられる範囲）

## 7. 比較のために、Vercel 側で確認すること
- [ ] Hobby（無料）プランの商用利用の定義（投げ銭リンクを置くだけでも商用扱いになるか）
- [ ] Pro の料金（1 人あたり月 20 ドルとされる）と、込みの転送量・超過料金

## 調べた結果の書き方
各項目に「結果・確認した日付・参照した URL」を書き足す。結果をもとに CTO が D-02（公開先とドメイン）と D-22（ホスティング）の推奨を確定する。
