## 0. まとめ（先に）

1. **見出しの「需要はある」は、問いと違うものに答えている（高）**。00 の「このジャンル」は「各自のスマホで・URL/QR で・対面で」まで含む。01 が「ある」と言えたのは**隣の需要（対面で短く遊ぶ。主に紙のゲーム）**で、ジャンルそのものは直接の根拠 0 件。PdM は「全体の結論は変えなくてよい」としたが、私は**見出しも変える**べきと考える：「**隣の需要はある。SUKIMA の形は未確認。机の上ではこれ以上決まらない**」
2. **判断の線は、今のままだと「ない」に倒れやすい所と「ある（または判定しない）」に逃げられる所が両方ある（高）**。「ない」側：28 日の再ホストは iPhone で消える（CTO）、試遊の 2 週間は集まる機会がない組を数える（PdM）、思い出す手段がまだない（J-10・J-11・J-16）、2 人の組は北極星に入らない。「逃げ道」側：「判定できない」に期限がない、「思い出す手段の不足が出たら弱いとしない」が毎回使える、試遊の組は PO の知り合い。§2 に一本化した線と、**期限つきの「判定できない」**を出す
3. **「知られていない」「思い出せない」「需要が弱い」は、段階で分けて測れる（高）**。試遊では全員が知っているので「知られていない」は起きない → 試遊は「思い出せない」と「弱い」を分ける場。一般公開では**見た人（SNS の表示・`?s=` の来訪）から部屋を作った割合**を見れば、「知られていない」と「見たのに作らない」を分けられる。01 にも PdM にもこの段がない
4. **J-11・J-10（できれば J-16）は試遊の前に入れる方を推す（中）**。4 組では「入れた組／入れない組」の比較はもともとできない（CTO の言う「比較ができなくなる」は失うものが小さい）。逆に入れないと、0 組だったときに必ず「思い出す手段がなかったから」という逃げ道が残る。PO の時間は 0、費用 0
5. **CTO の推奨「P2 は 7 日を主に」は、頻度の低い場面（SC-7 月 0〜2 回）では需要と関係なく低く出る（中）**。7 日も 28 日（全端末）も「ない」に倒れる。**28 日を Android・PC に絞ったものを主、7 日は参考**にし、母数が半分程度に減ること（幅が広がること）を線に書く

### 2.3 「判定できない」の期限（新しく足す）

- ② が 2027 年 7 月ごろ（D-41 の V-2 と同じ時期）に「判定できない（40 ルーム未満）」なら、**8 週だけ延ばし、それでも 40 に届かなければ、それ自体を結果として PO に出す**（「この形・この届け方では、需要を測れる規模まで人が来なかった」）【SM。8 週は仮定】

## 3. 「需要が弱い」「まだ知られていない」「思い出す手段がない」の切り分け

### 3.1 段階ごとに起きうるもの

| 段階 | 知られていない | 思い出す手段がない | 出しにくい（M1・M2） | 需要が弱い |
| --- | --- | --- | --- | --- |
| 試遊 | **起きない**（全員が遊んだ） | 起きる | 起きる | 起きる |
| 一般公開 | 起きる | 起きる | 起きる | 起きる |

→ 試遊は「知られていない」を除いた残り 3 つを分ける場。一般公開は §2.4 で「知られていない」を先に除く。

### 3.2 試遊での分け方（PdM §4 の 2 問目を、理由で分類する）

| 2 問目の答え | 読み方 |
| --- | --- |
| 開いた（PO・協力者以外が言い出した） | 需要がある側 |
| 思い出したが開かなかった：「出しにくかった」「場に合わなかった」 | 出しにくい（M1・M2）→ PdM §5 の ② |
| 思い出したが開かなかった：「ほかの遊び・話で十分だった」「気分じゃなかった」 | **需要が弱い**側 |
| 思い出さなかった・名前が出てこなかった・URL が見つからなかった | 思い出す手段がない → PdM §5 の ① |
| 機会がなかった | 判定に入れない（4 週で聞き直す） |

答えの選択肢は PdM が観察シートに入れる。直後の 3 分シートの「サイトの名前を覚えていたか」（PdM §4）と合わせて読む。

### 3.3 J-16・J-11 を試遊の前に入れるか

| 観点 | 入れる | 入れない |
| --- | --- | --- |
| 切り分け | 「思い出す手段がない」の逃げ道が小さくなり、0 組のときに「弱い」と言える | 0 組なら「思い出す手段がなかった」が常に残る（L-4） |
| 比較（CTO の懸念） | 入れた／入れないの比較はできない。**ただし 4 組では、組を分けた比較はもともと意味がない** | 「手段がないと開かれないか」は §3.2 の理由で分かる（比較ではなく聞き取り） |
| 実測（NORTH_STAR 優先順位 4） | 交絡を減らす方向 | — |
| PO の時間（1）・費用（5） | 0（AI の作業。S が 2〜3 本） | 0 |
| 体験（2）・セルフサーブ（3） | 一言・アイコンは邪魔にならない作りにする（Client） | — |
| 効き目の見込み | **J-11（退出時の一言・LINE に貼る）と J-10（作り直し導線）は全員に効く**。J-16（ホーム画面に追加）は追加する人が少ないとみられ【仮定】、効き目は小さい。iPhone の計測の改善も、追加した人の分だけ | — |

## 7. Gemini の調査が届いたときの突き合わせ方

### 7.1 読む前に決めておくこと（都合のよい読み方を防ぐ）

結論を動かしうるのは次の 4 種類だけ、と先に決めておく。それ以外の数字（市場規模の言い換えなど）は、増えても確度を上げない。

| 届いたもの | 動く箇所 |
| --- | --- |
| G-1 「対面で、各自のスマホで一緒に遊ぶ」行動の直接の調査（割合・頻度） | ジャンルの「未確認」→「間接の兆しあり」か「弱い兆し」。**一次の出典が確かめられたときだけ** |
| G-2 日本語・登録なし・ブラウザで、対面の短い遊びに寄せた競合 | §2.2 の「空き」。L-2 の 3 つ目の理由 |
| G-3 検索の量の動き（ワードウルフ・パーティーゲーム アプリなど） | §5.4 の机上の確認。季節の山（SC-5）の見込み |
| G-4 01 の数字と食い違う値（例：F-1・F-8・F-12） | 該当の行 |

### 7.2 手順（Marketing。05 の前に SM が確かめる）

1. `research-gemini.md` に、届いた本文をそのまま保存する（オーケストレーター）
2. 主張を 1 行ずつ「数字（出典あり）／数字（出典なし）／主張／競合の名前」に分ける
3. 出典のある数字は**元の資料を開いて**値・時点・対象を確かめる。開けなければ「要約のみ」。出典のない数字・開くと違う数字は採らない（生成 AI の調査は、存在しない出典や別の年の値が混ざることがある）
4. 01（04）の表と照らし、各行に「一致／食い違い／新しい／採らない」を付ける。食い違いは両方の出典と時点を並べ、どちらを採るかの理由を書く
5. 海外（主に米国）の数字は、国内の行動の根拠にしない（参考の列に置く）
6. 一致した数字が増えても、**同じ一次資料を両方が引いているだけなら、独立した裏付けとは数えない**
7. G-1〜G-4 に当たるものがあれば、どの箇所がどう動くかを 04 か 05 に「Gemini による差分」として書く。当たるものがなければ「結論は変わらない」と 1 行書く

### 7.3 時期

- 04 の改訂までに届けば 04 に入れる。届かなければ 04 は先に進め、届いたときに差分だけを 05 の前に足す。**Gemini を待って 05 を止めない**（結論はどちらにしても「机上では決まらない、試遊と計測で確かめる」で、それを変えうるのは G-1 だけのため）
