## 3 案の概要

### 案A「ドット・アクセント」（ドット絵が軸）

- **コンセプト**：夜のゲームセンターのような落ち着いた濃紺に、ドット絵のロゴ・アイコン・ミニゲーム演出だけを光らせる。本文と操作の文字は読みやすいゴシック体のまま。
- **ターゲットに合う理由**：25〜39 歳がファミコン〜DS で「みんなで遊んだ」記憶に触れる。瞬間ミニゲームのテンポ（短い指示・大きな文字・すぐ結果）はレトロゲームの文法そのもの。PdM 所見 §6.3 のとおり、ドットはロゴ・見出し・ミニゲーム・演出だけにした。ミニゲームの「画面」はライトでも濃紺のままにして、ゲーム機の画面に見立てている（明るい車内でも指示の黄色が 12.9:1 で読める）。
- **懸念**：ドットフォント（DotGothic16）の漢字は小さいと潰れるので、見出しは 19px 以上に限る。作り込みが甘いと「昔のフリーゲーム」に見える（アイコンは 12×12 グリッド・色数 4 のルールで品質をそろえる必要がある）。ワードウルフ・大富豪の画面ではドットの装飾を減らす必要がある。
- **ロゴ**：段差のある「隙間」から光が漏れる 10×10 の正方形。16px のファビコンでも形が残る。

### 案B「ポップ・ステッカー」（ドット絵以外）

- **コンセプト**：太い墨線・平塗り・ずらした影のステッカー調。ミニゲームの指示は極太の描き文字風で、傾けて叩きつけるように出す。
- **ターゲットに合う理由**：一目で「遊ぶもの」と伝わる勢いがある。「よけろ！」「ふくらませろ！」のくだらなさを、雑誌の挿絵のような大人のユーモアで強められる。OGP のサムネイルで目立ちやすい。
- **懸念**：派手で、会議前の画面共有（SC-2）や話す系ゲームでは主張が強い。丸い形と原色が増えると子どもっぽく寄る（パステル化・キャラ化は禁止）。極太フォント（Dela Gothic One）は本文に使えない。「ポップなフラット」は Web で既視感がある。暗い店内では黄色い面積が眩しい。

### 案C「余白とハンコ」（ドット絵以外・現状路線の強化）

- **コンセプト**：現状の生成り×テラコッタを磨き、線画アイコンと大きな余白で整える。遊ぶのは判定だけ：「クリア！」は朱の丸印、「ミス！」は藍の角印のハンコで押す。
- **ターゲットに合う理由**：仕事の画面共有（SC-2）や電車内（SC-3）でも浮かない品位があり、現行実装からの移行がいちばん軽い。ハンコは日本の大人に通じる小さなユーモアで、形（丸と四角）と色の両方で成否を区別できる。
- **懸念**：PdM が指摘した「意識高い SaaS 風・ゲームらしさが弱い」は残る。トップを開いた 3 秒で「ゲームだ」と伝わる力は 3 案で最も弱い。OGP サムネイルでも地味。記憶のフックは輪のロゴとハンコだけ。

## Designer の推奨：案A「ドット・アクセント」

1. **ターゲットの共通体験に効く記憶のフックになる**（06 §5.1 Should）。ロゴの「隙間から漏れる光」とドットのアイコン列は SUKIMA の顔になり、OGP・ファビコン（16〜32px）でも形が残る。案C にはこれがない。
2. **品位と遊び心の両立がいちばん素直**。画面の大部分は濃紺の落ち着いた UI とゴシック体の本文で、P1 が貼っても、P3 が電車で開いても恥ずかしくない。ふざけるのはミニゲームの画面と判定だけ、と強弱が付けられる（06 §6.3-5）。案B は常に賑やかなので、話す系ゲームや会議前では強すぎる。
3. **最優先シーン SC-1 / SC-3 の両方に強い**。暗い店内ではダークが眩しくない。明るい車内では、ミニゲーム画面を濃紺に固定しているため、指示の黄（12.9:1）と時間バーが周りの明るさに左右されない。
4. **量産のルールが明快**。アイコンは「12×12・4 色・墨の縁」、部品は「1 ドット欠けの角」と決めれば、ゲームが倍に増えても同じ作法で作れる（06 §5.6）。

**条件**：(a) ドット書体は見出し・指示・数字だけにし、19px 未満では使わない。(b) ワードウルフ・多数派・大富豪の画面ではドットの装飾をアイコンと見出しだけに抑える。(c) V2（5 秒テスト）で「古い・安っぽい」が多ければ、案C のトークンへの切り替えを第 2 候補にする（構造は 3 案で共通にしてあるので、トークンとアイコンの差し替えで移れる）。

### 3 案に共通する提案（どの案を採っても入れたい）

- **招待 URL から来た人の参加画面**：ルームコードを大きく見せ、「友達からの招待です」「登録・インストールは不要です」を添える。「ユウキさんたち 3人が待っています」は、参加前に部屋の人数と名前を受け取る仕組みが必要なので、Backend・CTO と要相談（`RoomHandle` の契約変更を伴う可能性あり）。
- **ゲスト視点のロビーの並び**：スマホでは「次に遊ぶゲーム（ルールと待機中の表示）」→「メンバー」→「ゲームを選ぶ（ホストのみ操作）」の順にし、ゲストが最初に「これから何が始まるか」を見られるようにする。
- **ラッシュの進み具合を絵で見せる**：数字のスコアは出さず、「STAGE n」に加えて、ステージの道のり（済み・現在・5 ステージごとのスピードアップの旗）とハートで示す。
- **ミスの文言**：「ミス！」の下に「ライフが1つ減った」（案C は「ライフ −1」）。責める言い方を避ける。
- 絵文字のアイコンは、案ごとのルールで描いた SVG に置き換える（端末による絵文字の差をなくす）。

## 採用後の実装の進め方（Client 向け）

1. **トークンを CSS 変数として `src/styles.css` に入れる**。現行の `:root` / `@media (prefers-color-scheme: dark)` / `[data-theme]` の三段構えはそのまま使い、各モックの `:root` ブロックの値で置き換える。既存の変数名（`--bg` `--surface` `--surface-2` `--border` `--text` `--muted` `--accent` `--accent-ink` `--good` `--bad` `--radius`）はそのまま残すので、既存のクラスは自動で新しい色になる。追加する変数は案A なら `--edge` `--heart` `--screen` `--screen-text` `--screen-dim` `--px-ink` `--g-<ゲームID>` `--font-body` `--font-dot`。
2. **フォント**：`index.html` で Google Fonts を `display=swap` で読み込む（案A：DotGothic16＋Noto Sans JP）。ドット書体は `.dot` などのクラスと見出しの要素だけに当てる。
3. **ドット絵は SVG のコンポーネントにする**：`src/components/PixelSprite.tsx`（文字列のグリッド → `<rect>`、`shape-rendering="crispEdges"`、倍率は整数だけ）と `src/components/sprites.ts`（ロゴ・ハート 3 種・○×・的・ゲームアイコン）。色はクラスで CSS 変数を参照するので、テーマ切り替えに自動で追従する。モックの生成に使ったグリッドの定義はそのまま移植できる（`design/mockups/a-pixel.html` の SVG に入っている）。
4. **ゲーム色とアイコン**：`GameDef` に `emoji` と並べて任意の `icon`（スプライト名）を足すか、`registry` のゲーム ID → スプライトの対応表を UI 側に持つ。`GameDef` の型を変えるなら CTO の承認を取る。対応表なら型の変更は不要。
5. **共通部品から順に置き換える**：`.btn` / `.panel` / `.input` → `Hearts.tsx`（♥ の文字を満タン／空のスプライトへ）→ `MicroStage.tsx` の `.micro-title` / `.micro-verdict` / `.micro-timebar`（区切りのある時間バーと ○× の判定）→ `rush/View.tsx` の `.rush-header`（ステージの道のり）→ Home → Room（参加画面・ロビーの並び替え）。瞬間ミニゲーム 10 種の中身は、背景・指示・時間バー・判定を共通部品にそろえてから個別に調整する。
6. **動き**：判定のスタンプや帯は 150〜250ms 程度。`prefers-reduced-motion: reduce` では動きをなくす。
7. **確認**：360px と 1280px の両方、ライト／ダークの両方で見た目を確認する。本文 4.5:1、大きい文字 3:1 以上（モックの主要な組み合わせは上の表のとおり計測済み）。タップ領域は 44px 以上。`typecheck` / `test` / `build` を通す。
8. **OGP（MVP-15）**：採用案のロゴ＋ゲームアイコン列＋「URLを送るだけで、すぐにみんなで。」「登録不要」の 1200×630 を Marketing と作る。中央 630×630 に要素を収めて、正方形に切られても成立させる。

## 補足

- モックの名前（ユウキ・ミサキ・ケンジ・ハルカ）、部屋コード `K7MQ`、ステージ数などはすべて仮のもの。
- 文言は現行アプリ（`Home.tsx` / `Room.tsx` / `registry.ts` / `micro/core.ts` / `tuning.ts`）に合わせた。上の「共通する提案」の文言は新しい提案。
- PC 幅のロビーの右列には、実際のアプリではチャット欄（幅 960px 以上で常時表示）が入るが、モックでは省略した。
- 案B のワードウルフのアイコンは猫にも見えるので、採用するなら描き直しが必要。
