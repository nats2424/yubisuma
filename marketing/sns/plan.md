## PO の方針（確定事項として扱う）

1. PO は撮影も顔出しもしない
2. 実在するゲーム画面は、本物の録画（デモモードを Playwright で自動操作）を使う
3. 思い描くユースケース（例：それぞれの家から LINE 通話しながら SUKIMA で遊ぶ様子）は AI 動画生成で表現してよい。その場合は **AI 生成のラベルを付け、ゲーム画面そのものは AI で偽造しない**（AI のシーン＋本物の画面録画の組み合わせ）
4. PO は個人の SNS アカウントを持っていない。新しく作るところから始める
5. 投稿は当面 PO の承認制（Human-in-the-Loop）

## 1. 新規アカウントの立ち上げ

### 1.1 個人アカウントか、SUKIMA 名義か（推奨のやり直し）

10 §2.5 と D-19 では「PO の個人アカウントで『作っています』と発信し、SUKIMA 名は名前の確保だけ」を推奨していた。理由は「フォロワー 0 の新しいアカウントより、既存の個人アカウントのほうが最初の反応を得やすい」だった。**PO に個人アカウントがないなら、どちらを作ってもフォロワー 0 から始まる**ので、この理由はなくなる。

| 観点 | 新しく PO の個人アカウントを作る | SUKIMA 名義のアカウントを作る（推奨） |
| --- | --- | --- |
| 最初の反応 | どちらも 0 から。差はない | 同じ |
| 顔出し・撮影なしとの相性 | 「人」を見せる発信なのに顔も声も出せないので、中身が薄くなりやすい | もともと「サービス」が主役なので、顔なしでも不自然でない |
| 名前を覚えてもらう | 個人名とサービス名の 2 つを覚えてもらう必要がある | 投稿のたびに「SUKIMA」が目に入る（07 J-11「サイト名を覚える機会がない」の手当てにもなる） |
| TikTok・ショートとの相性 | 個人の発信と、ゲーム紹介動画が混ざる | ゲーム紹介動画のアカウントとして一貫する |
| 運用の移行 | Phase 2 で SUKIMA アカウントに乗り換え、フォロワーを移す手間が出る | 乗り換えが要らない。10 §2.5 の「本格運用に切り替える基準」を待たずに済む |
| プライバシー | 「誰が作っているか」が個人に結び付きやすい | 運営者の実名を出さなくてよい（ただし問い合わせ窓口は 08 U5 のとおりサイトのフォーム） |
| 人の手の形跡（量産判定の回避） | 出しやすい | 「中の人」の一人称の投稿（開発の裏話・試遊で笑ったこと）を混ぜて出す |
| 将来の引き継ぎ | 個人に紐づくので渡せない | 専用の Google アカウント・メールで作れば、将来ほかの人に運用を渡せる |

**推奨：SUKIMA 名義で作り、文体は「SUKIMA を作っている人」の一人称**（例：「今日はミニゲームを1本足しました」）。プロフィールに「個人開発」と書き、人が作っていることは伝える。実名・顔・声・住んでいる地域は出さない。これは D-19 の変更になるので、PO 判断事項 S-1 とする。

ステルスマーケティング規制（2023 年 10 月施行の景品表示法の告示）との関係：SUKIMA 名義の投稿は運営者自身の宣伝なので問題ない。**PO や知人が「一般の人のふり」をして紹介投稿をするのはやめる**（頼むときは「作っている人の知り合い」であることを書いてもらう。詳細は要確認）。

### 1.2 どの SNS から始めるか

ターゲットは 25〜39 歳の日本の社会人で、LINE グループ通話・Discord で集まる仲間内（06 §1.1・SC-4）。SUKIMA の価値は「URL を開けばすぐ遊べる」なので、**投稿から URL に飛べるか**を重く見た。

| SNS | 25〜39 歳の日本の利用 | フォロワー 0 からの届きやすさ | URL への導線 | 顔なし・動画なしで始められるか | API・自動化（調査時点・要確認） | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| **X** | 多い。`#個人開発` の文化があり、作り手の発信に反応する人がいる | 低め（フォロー関係とおすすめ欄。最初は伸びにくい） | **投稿に URL を直接貼れる**（外部リンクの表示が抑えられる傾向があるという指摘もあり、要確認） | **できる**。文章＋静止画で、録画の仕組みができる前から始められる | 自動投稿の API は有料プランが中心で条件がよく変わる。公式の予約投稿機能（Web）は無料で使える見込み（要確認） | **1 番目** |
| **YouTube ショート** | 多い（YouTube 自体の利用が広い） | **高い**（フォロワーに関係なく、おすすめに出る） | 説明欄・固定コメントのリンク（ショートからの外部リンクの扱いは要確認） | 動画が必要 | API は無料のクォータ（1 日 10,000 ユニット、1 本約 1,600 ユニット）。未審査の API プロジェクトからのアップロードは非公開になる制約がある認識（要確認） | **2 番目（2 週目〜）** |
| **TikTok** | 20 代中心だが 30 代にも広がっている | **高い**（おすすめに出る） | プロフィールのリンクのみ（使える条件は要確認）。投稿からのクリックは弱い | 動画が必要 | **公開投稿の API はアプリ審査（2〜6 週間）が必要**。未審査は非公開投稿のみ。API では TikTok の楽曲を付けられない | **3 番目（3 週目〜）** |
| Instagram リール | 多い | 中〜高（リールはおすすめに出る） | プロフィールのリンク、ストーリーズのリンク | 動画か画像が必要 | API には Facebook ページ連携とビジネス（プロ）アカウントが必要。手順が多い | 名前の確保のみ。4 週目に判断 |
| Threads | 中（Instagram 利用者が中心） | 中 | 投稿にリンクを貼れる | できる（文章中心） | API で 1 日 250 投稿まで。Instagram アカウントが前提 | 名前の確保のみ。X の投稿を少し変えて出す候補 |

**X から始める理由**

1. **今すぐ始められる**：短尺動画には Client の「録画モード」（デモモードの帯を消す・乱数を固定する。10 §2.3）が必要で、まだない。X は文章と静止画（`design/implemented/` と同じ方法で撮るスクリーンショット）で、開発の裏話から始められる。新規アカウントは数週間の慣らしが要るので、動画を待たずに始めるほうがよい
2. **URL に直接飛べる**：北極星指標（楽しまれたルーム）に効くのは「開いて遊ぶ」こと。投稿に URL を貼れる X が一番近い
3. **作り手の発信が受け入れられる**：`#個人開発` `#ゲーム開発` の文化があり、フォロワー 0 でも同じ立場の人から最初の反応を得やすい（推定）。Phase 1 の「知人経由・小さく」と相性がよい
4. 弱点（フォロワー 0 だと届きにくい・自動投稿の API が高い）は、2 週目からの YouTube ショート（おすすめで届く）と、段階 1 の手動の予約投稿で補う

**YouTube ショートを TikTok より先にする理由**：Google アカウントで作れて手順が軽い、ブランドアカウントにすれば将来ほかの人に渡せる、段階 2 の API が無料で使える、AI 生成ではない本物の録画が主力なのでラベルの問題が起きにくい。TikTok はおすすめの力が強いが、URL への導線が弱く、公開投稿の API に審査があるので、動画のストックが 4 本以上たまった 3 週目から手動で始める。

### 1.3 アカウント名の案

「SUKIMA」単独の名前（`@sukima`）は短く一般的な語なので、**どの SNS でも取られている可能性が高い**（未確認）。全 SNS で同じハンドルをそろえることを優先し、候補を順に試す。

| 順 | ハンドル | 理由 | 懸念 |
| --- | --- | --- | --- |
| 1 | `sukima_game` | 何のアカウントか一目で分かる。短い | 取られている可能性がある |
| 2 | `sukima_asobi` | 「隙間に遊ぶ」。日本語のニュアンスが出る | ローマ字が読みにくい人もいる |
| 3 | `playsukima` | 動詞＋名前で、ドメイン名にも転用しやすい | 英語っぽさが強い |
| 4 | `sukima_minigame` | 説明的で検索に強い | 長い（X は 15 文字まで。ちょうど 15 文字） |
| 5 | `sukima5min` | 「5分」の訴求（C2・C5）と結び付く | 数字入りは覚えにくい |

- 表示名（全 SNS 共通）：**「SUKIMA｜URLを送るだけのミニゲーム」**（文字数の上限は SNS ごとに要確認。入らなければ「SUKIMA｜ミニゲーム集」）
- 独自ドメインを取る場合（D-02）は、ドメイン名とハンドルをそろえるとよい（例：ドメインが `playsukima.〜` ならハンドルも `playsukima`）。D-02 と同時に決めるのが理想
- 確保する SNS：X・YouTube・TikTok・Instagram・Threads の 5 つ（Threads は Instagram のアカウントで作る）。始めない SNS も**名前だけ先に確保**し、プロフィールに「準備中」とサイトの URL を書く。長期間使わないと削除される規定がある SNS があるので、月 1 回ログインする（規約は要確認）

### 1.6 立ち上がり期の投稿頻度

調査の基準「**新規アカウントは 1 日 1 本、成長期でも 1 日 2 本まで。頻度は数週間かけて上げる**」に従う。加えて、PO の作業時間（週 2 時間以内）の範囲に収める。

| 時期 | X | YouTube ショート | TikTok | 合計／週 |
| --- | --- | --- | --- | --- |
| 1 週目 | 3 本 | （チャンネルを作るだけ） | （名前の確保のみ） | 3 |
| 2 週目 | 4 本 | 2 本 | — | 6 |
| 3 週目 | 5 本 | 3 本 | 2 本 | 10 |
| 4 週目 | 5〜7 本（1 日 1 本まで） | 3 本 | 3 本 | 11〜13 |

- ハッシュタグは関連する 3〜5 個まで（例：`#ミニゲーム` `#個人開発` `#ブラウザゲーム` `#ワードウルフ` `#通話`）。流行のタグに無関係に乗らない

### 1.7 最初の 4 週間の計画

前提：08 の Phase 0（試遊）〜Phase 1（限定公開）にまたがる。**公開前は URL を貼らず「作っています」の発信だけ**、限定公開後に URL を貼る。大きな告知はしない（08 §4・10 §2.1）。録画モード（Client）ができる時期によって 2 週目以降の動画はずれる。

| 週 | 目的 | PO | AI（SNS Marketer） | 投稿の中身 |
| --- | --- | --- | --- | --- |
| 0（準備） | アカウントを作る | 専用 Google アカウント作成、5 つの SNS で名前を確保、2 段階認証、プロフィール設定（合計 2〜3 時間） | 名前の候補順、手順書、プロフィール文、アイコン・ヘッダーの依頼（Designer）、録画モードの依頼（Client）、1 週目の投稿パック | — |

## 2. 動画の作り方

共通ルール（10 §2.3 を引き継ぐ）

- 縦 9:16（1080×1920）。字幕・テロップ必須。**音なしで成立させる**（通話中・電車の視聴を想定）
- ゲーム画面・判定・結果は本物。操作のタイミングだけ台本で決める。画面の加工で結果を変えない
- 「会話」は字幕で付け、**「※プレイは自動操作による再現です」**を画面の隅に常に出す。実在の人の反応のように見せない
- 名前は架空のニックネーム（ユウキ・ミサキ・ケンジ・ハルカ）。デモモードの帯・ブラウザの枠・通知・実在のチャットは映さない
- 文字は案B のトーン（Dela Gothic One の見出し・墨のフチ・トマト `#ff5b3a`・黄 `#ffd23f`）。テロップの型は Designer に確認する
- 1 投稿 1 メッセージ。最初の 1 秒で「何のゲームか」が分かること
- 締めの 2 秒：C5「その5分、SUKIMAで。」＋（公開後は）URL の文字。SNS によって URL をタップできないので、「プロフィールのリンクから」を添える

### 2.1 型 A：本物のゲーム画面の自動録画＋字幕

**作り方**：デモモード（同じブラウザの別タブ同士で遊べる）を Playwright で 1〜4 タブ開き、台本どおりに操作して各タブを録画 → ffmpeg で縦に並べて合成（4 人なら 2×2、ひとり用は 1 画面）→ 字幕・テロップ・効果音を重ねる。録画には Client の「録画モード」（帯を消す・乱数を固定してお題を選べる・名前を指定できる）が必要（10 §2.3 で依頼済み、未実装）。

- 尺：**15〜20 秒**（TikTok・ショート）。X は同じ動画を 10〜15 秒に詰めた版も試す
- 台本テンプレート

| 時間 | 中身 | 例（ふくらませろ！） |
| --- | --- | --- |
| 0.0〜1.5 秒（フック） | ゲームの指示の文字を画面いっぱいに出し、問いかけを重ねる。動きのある瞬間から始める（タイトル画面から始めない） | 「ふくらませろ！」の指示＋テロップ「4人で同時に。誰が割る？」 |
| 1.5〜3 秒（状況） | 誰が・どこで（通話中の 4 人／ひとり）を一言で | 「通話中の4人」 |
| 3〜14 秒（プレイ） | 本物の画面。見どころの直前にテロップで予告（「ここで…」） | 1 人ずつ割れていく。最後の 1 人が慎重すぎて時間切れ |
| 14〜17 秒（オチ） | 判定・結果の画面＋ひとことのツッコミ | 「慎重すぎてもダメ」 |
| 17〜20 秒（締め） | C5＋URL（またはプロフィールへの誘導） | 「その5分、SUKIMAで。」 |

- 冒頭のフックの型（どれか 1 つ）：①指示の文字＋問い（「文字の色は？」「あなたは何色に見える？」）②結果の先出し（「全員割った」→ 巻き戻し）③挑戦状（「12ステージ。超えられる？」）④あるある（「通話のネタが切れたとき」）
- AI ラベル：型 A は AI 生成の映像を使わないので不要。ただし字幕の文やナレーションに AI 音声を使う場合は、各 SNS の基準で表示が要るか要確認（当面は AI 音声を使わず、字幕だけにする）

### 2.2 型 B：AI 生成のユースケースシーン＋本物の画面の合成

**作り方**：冒頭（と、必要なら最後）に AI 動画生成で「使われている場面のイメージ」を作り、中盤は型 A と同じ本物の画面録画にする。AI の部分は**場面の雰囲気だけ**で、スマホやパソコンの画面に映る内容は AI に描かせない（画面は黒・ぼかし・後から本物の録画をはめ込む）。

- 尺：**20〜25 秒**（AI シーン 3〜5 秒＋本物の画面 12〜15 秒＋締め 3 秒）
- AI 生成ツールの候補（調査時点・料金は要確認）：Seedance 2.5（fal.ai などの API 経由の従量課金。参照画像で一貫性を出しやすい）、Kling AI。Luma・Runway は挿入映像向け。試作は Google Veo 3 で可。最初は 1 本ずつ手で生成し（段階 1）、良いプロンプトの型を残す
- 台本テンプレート

| 時間 | 中身 | ラベル |
| --- | --- | --- |
| 0.0〜2.0 秒（フック） | AI のシーン：夜、それぞれの部屋でスマホを持つ 3〜4 人を分割画面で（顔は映さないか、手元・後ろ姿・遠景）。テロップで「通話のネタが切れたら」 | 画面上に**「AI生成のイメージ映像」**を常に表示 |
| 2.0〜4.0 秒 | AI のシーン：1 人がスマホを操作する手元（画面の中身は映さない）。テロップ「URLを1本、貼るだけ」 | 同上 |
| 4.0 秒 | はっきり切り替える（白フラッシュなど）。テロップ「ここから実際のゲーム画面」 | — |
| 4.0〜18 秒 | 本物の画面録画（招待 URL から参加 → ロビー → ゲーム） | 画面の隅に「実際のゲーム画面（自動操作による再現）」 |
| 18〜21 秒 | 締め（C5＋URL） | — |

- **AI ラベルの付け方（2 重にする）**
  1. 動画の中：AI の部分の間ずっと「AI生成のイメージ映像」を表示し、本物の部分には「実際のゲーム画面」と表示する。境目を見える形で切り替える
  2. 投稿のとき：各 SNS の「AI 生成コンテンツ」の表示機能をオンにする（TikTok の AI 生成コンテンツのラベル、YouTube の「改変または合成されたコンテンツ」の申告、Instagram の AI 情報のラベルなど。名前と場所・義務の範囲は要確認）。投稿文にも「※冒頭はAI生成のイメージです」と書く
- 守ること
  - **ゲームの画面を AI で作らない**。AI のシーンの中のスマホ画面に SUKIMA の画面を描かせない
  - **実在の人物・有名人に似せない**。顔のアップを避け、手元・後ろ姿・シルエットにする（実在のユーザーの反応と誤解されないため、不気味さを避けるためでもある）
  - LINE・Discord のロゴや画面そっくりの UI を描かせない（商標・誤認の防止）。テロップで「LINE通話しながら」と言葉で書くのは可（10 §1.3 の「LINE・Discord を敵にしない／相乗り」）
  - 子どもを登場させない（帰省の場面でも大人だけ、または手元だけ）
  - 生成ツールの利用規約で、商用利用・SNS 投稿が許されているプランかを確認する（要確認）

## 3. 自動化パイプラインの段階的な導入

調査の 3 段階（試行 → ワークフロー構築 → 多プラットフォーム展開）と 5 工程（企画 → 素材生成 → 統合 → 人の承認 → 配信と記録）を、個人開発・月 0〜5,000 円の規模に合わせた。**どの段階でも、公開の前に PO の承認を挟む**（全自動にはしない）。

### 3.1 段階 1：手動投稿＋AI が投稿パックを作る（今〜少なくとも 4 週間）

| 工程 | 誰が・どうやって | 費用 |
| --- | --- | --- |
| 企画 | AI（SNS Marketer）が、前週の数値と 10 の企画案・季節から、翌週の投稿を決める | 0 円 |
| 素材生成 | AI がデモモードを Playwright で録画、スクリーンショットを撮る。型 B の AI シーンは月 1〜2 本だけ生成サービスで手作り（PO がアカウントを持つか、使わないかは S-5） | 0 円（型 B の月だけ従量課金） |
| 統合 | AI が ffmpeg で合成・字幕・尺の調整。SNS ごとに冒頭と尺を変えた版を書き出す | 0 円 |
| 人の承認 | PO が投稿パックを見て承認・修正指示 | 0 円 |
| 配信 | **PO が各 SNS の公式の予約機能で予約**（X は Web の予約投稿、YouTube は YouTube Studio、TikTok は TikTok Studio（Web）の予約、Instagram・Threads は各アプリまたは Meta Business Suite。どれも無料の見込みで、使える条件は要確認） | 0 円 |
| 記録 | PO が週 1 回、数値を表にコピー → AI が振り返り | 0 円 |

**投稿パックの置き場所と中身**：`marketing/sns/packs/<年>-W<週番号>/` に、`posts.md`（投稿ごとに：SNS・日時・本文・ハッシュタグ・計測 ID 付きの URL・AI ラベルの要否・動画ファイル名）、動画（SNS ごとの版）、画像、返答案、チェック表（顔・個人情報・帯・通知が映っていないか、ラベル、音のライセンス）を入れる。PO が見やすいよう、オーケストレーターが要点と動画を PO に渡す。

**段階 1 の週の流れ（例）**

| 曜日 | AI（SNS Marketer） | PO | PO の時間 |
| --- | --- | --- | --- |
| 月 | 先週の振り返り（PO が日曜に渡した数値から）、翌週の企画 | — | — |
| 火 | 投稿パックを完成（投稿文・動画・日時・返答案） | — | — |
| 水 | — | **投稿パックを確認し、承認か修正指示**（スマホで動画を見る） | 30〜45 分 |
| 木 | 修正を反映した最終版 | **翌週 7 日分を各 SNS で予約**。型 B は AI ラベルのスイッチをオン | 20〜30 分 |
| 毎日（任意） | 前日の返信・コメントへの返答案（PO が貼った場合） | 通知に目を通して返す。炎上しそうなものは返さずに相談 | 5 分 × 3〜4 回 |
| 日 | — | **各 SNS の分析画面の数値を表にコピー**（またはスクリーンショット） | 10 分 |

合計：PO は週 1.5〜2 時間（10 §2.5 の「週 1〜2 時間」に収める。超えそうなら投稿本数を減らす）。

### 3.2 段階 2：承認ボタン付きの自動投稿（条件を満たしたら）

**始める条件**（すべて満たしたら PO に提案する）

1. 段階 1 を 4 週間以上続け、投稿パックの型（台本・字幕・SNS ごとの調整）が固まった
2. 3 つ以上の SNS で投稿していて、**予約の作業が PO の負担になっている**（週 30 分以上）
3. シャドウバンの兆候がない（§4.5）
4. 限定公開（Phase 1）が始まっていて、投稿に URL を載せられる
5. PO が月の費用（§5）を承認した

**構成（推奨）**：AI が投稿パックを作る → PO のスマホに「動画・投稿文・日時」と**承認ボタン**を送る → 承認されたものだけ、投稿ミドルウェアの API で予約投稿 → 投稿の URL を記録。

承認の受け取り方の候補（どれも要確認）

| 方法 | 内容 | 費用 | 長所・短所 |
| --- | --- | --- | --- |
| Telegram のボット＋n8n | 調査どおりの形。n8n が承認ボタン付きのメッセージを送り、押されたら投稿 | n8n を自分のパソコンや無料のサーバーで動かせば 0 円、n8n のクラウド版は有料（要確認） | ボタンで完結して手軽。n8n を動かし続ける場所が要る |
| GitHub の Pull Request＋GitHub Actions | 投稿パックを PR にし、PO がマージ（＝承認）したら Actions がミドルウェアの API を呼ぶ | 無料枠の範囲で 0 円の見込み（要確認） | 既存のリポジトリの流れに乗る。PO が GitHub に慣れていないと押しにくい |
| Make.com | ノーコードで承認の流れを作る | 無料枠あり、超えると有料（要確認） | 設定が簡単。無料枠の回数制限 |

### 3.3 段階 3：多プラットフォーム展開と改善の自動化（条件を満たしたら検討）

**始める条件**

1. 08 の **Phase 2（PMF 条件を満たした拡大期）に入った**（PMF 前に投稿量を増やしても指標が濁るだけ）
2. 段階 2 を 8 週間以上、問題なく運用できた（シャドウバンの兆候なし、承認の滞りなし）
3. SNS ごとの数値が 8 週間分以上たまり、「どの冒頭・どのゲームが伸びるか」を比べられる
4. 予算の上限を PO が見直した（段階 3 は月 5,000 円を超える見込み）

**中身**：企画（スプレッドシートのテーマ → LLM が冒頭・台本・生成プロンプトを作る）と統合（ffmpeg・Creatomate 等）の定時実行、SNS ごとの最適化（冒頭・尺・文・時間帯）、反応のデータを企画に戻す。投稿は 1 日 2 本まで。**人の承認は残す**（外すかどうかは PO の判断。推奨は外さない）。調査にある FlowShorts・InVideo AI のような「生成から投稿まで全自動」のサービスは、テンプレート・AI 音声・ストック素材だけの量産になりやすく、量産判定のリスクと「本物の画面を使う」方針に合わないので使わない。

## 4. リスクと守ること

### 4.1 AI ラベル

- 型 B（AI シーンあり）は、**動画の中の表示＋各 SNS のラベル機能＋投稿文の注記**の 3 つで示す（§2.2）
- 型 A は AI 生成の映像を含まないのでラベル不要。ただし AI で作った画像（サムネイルの背景など）を使う場合は、各 SNS の基準でラベルが要るか確認する
- 各 SNS の基準（どこまでが「リアルな AI 生成」か）は変わるので、型 B を出す月の初めに AI が公式のヘルプを確認し、投稿パックに「確認日」を書く（AI はヘルプページを読むだけで、ログイン・送信はしない）

### 4.2 量産判定の回避

- テンプレート・AI 音声・ストック素材だけで作らない。**本物のゲーム画面・中の人の一人称の文・試遊で起きたこと**で、人の手の形跡を残す
- 同じ台本の使い回しは、ゲーム・冒頭・オチを変えて最低 2 週間あける
- 1 日 1 本（成長期でも 2 本）を守る。まとめて投稿しない
- フォロワーの購入、相互フォロー・いいね回りの集団への参加、懸賞（フォロー&リポスト）はしない（10 §2.2 のとおり）

### 4.3 同じ動画の使い回し

- 同じ動画を各 SNS に無加工で同時に出さない。**SNS ごとに冒頭 1.5 秒（フックの型）・尺・テロップの一部・投稿文を変える**。書き出しは AI が SNS ごとに行う
- 他の SNS の透かし（ロゴ）が入った動画を別の SNS に出さない（元の動画は透かしなしで手元に保管）
- 公開日をずらす（例：ショート → 翌日 TikTok → 翌々日 X）

### 4.4 音声・音楽のライセンス

- 基本は**音なしで成立**させ、BGM はなくてもよい。付けるなら商用利用が明記された素材だけを使い、出典とライセンスの条件を投稿パックに記録する（YouTube オーディオライブラリ、TikTok の商用楽曲ライブラリなど。条件は要確認）
- 流行の楽曲・既存のゲームの効果音・キャラクターの声に似せた音は使わない
- AI 音声（ElevenLabs など）は段階 1 では使わない。使うなら商用ライセンスのあるプランで、実在の人の声に似せない
- AI 動画生成で作ったものも、生成サービスの商用利用条件を確認する

### 4.5 シャドウバンの兆候と対処

| 兆候（調査の基準＋SNS Marketer の追加） | 対処 |
| --- | --- |
| 投稿後 24 時間の再生数・表示回数が、直近の平均の 30% 以下の状態が 3 日以上続く | 問題がありそうな投稿（ラベル漏れ・使い回し・過度な宣伝・ハッシュタグの付けすぎ）を見直し、**7〜14 日間は投稿と自動化を止める** |
| ハッシュタグ検索や、ログインしていない状態の検索で自分の投稿が出ない | 同上。ハッシュタグを 3 個以下に減らして再開 |
| 各 SNS のアカウントの状態のページ（TikTok・Instagram・YouTube Studio にある。場所は要確認）に警告が出る | すぐ PO に報告。異議申し立てが必要なら PO が行う（AI は文案だけ） |
| フォロワーが急に減る、ログインを求められる、知らない連携アプリがある | 乗っ取りを疑う。PO がパスワード変更・連携アプリの解除・2 段階認証の確認 |

止めている間は投稿を消して回らない（大量の削除自体が不自然な行動に見えるおそれがある）。再開後は 1 日 1 本以下から。

### 4.6 そのほか

- **映り込み**：録画のたびにチェック表で確認（顔・実名・通知・デモモードの帯・ブラウザの枠・実在のチャット）。動画のファイルの中の情報（撮影者名など）も消す
- **誇張しない**：「何人でも」（上限 10 人）、「遅延ゼロ」など実際と違うことは言わない（10 §1.1）。他社名を使った比較をしない
- **炎上・返信**：批判・政治・差別に触れる返信には反応しない。炎上しそうなものは PO に相談（ロールの判断基準）
- **アカウントの安全**：パスワード・認証コード・バックアップコードを AI に渡さない、チャットに貼らない。ミドルウェアの API キーは段階 2 で安全な場所（GitHub の Secrets など）に保管し、リポジトリにコミットしない
- **公開前の発信**：限定公開の前に URL を貼らない。試遊グループの情報（名前・やりとり）を本人の同意なく投稿に使わない

## 5. 費用と PO の作業時間の見込み（すべて仮定・要確認）

円換算は 1 ドル＝150 円の仮定。AI 動画生成は 1 本（数秒のクリップ 2〜3 本）あたり数十〜数百円と仮定しているが、**実際の単価は生成サービス・解像度・秒数で大きく変わるので、使う前に確認する**。

| 段階 | 主な費用 | 月額の見込み（仮定） | PO の時間 |
| --- | --- | --- | --- |
| 立ち上げ（1 回だけ） | アカウント作成はすべて無料の見込み。電話番号は PO の手持ちを使う | 0 円 | **2〜3 時間**（5 SNS の登録・2 段階認証・プロフィール設定） |
| 段階 1 | 投稿・予約は各 SNS の公式機能で 0 円。録画・合成は手元の道具（Playwright・ffmpeg）で 0 円。型 B を作る月だけ AI 動画生成 | **0 円**（型 B の月は 〜1,500 円程度） | **週 1.5〜2 時間** |
| 段階 2 | 投稿ミドルウェア（Upload-Post なら月 16 ドル〜）、承認の仕組み（n8n を自分で動かすか GitHub Actions なら 0 円）、型 B の AI 動画生成 | **月 3,000〜4,500 円程度**（ミドルウェア 約 2,400 円＋AI 動画 〜1,500 円＋予備） | **週 1 時間前後**（承認 30〜40 分・返信 15 分・数値は自動で記録できれば 0） |

予算（月 0〜5,000 円）に収まるのは段階 2 まで。段階 2 でも、ミドルウェアの無料枠で足りるなら 0 円に近づく（無料枠の本数・対応 SNS は要確認）。
